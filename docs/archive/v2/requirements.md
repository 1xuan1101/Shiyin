# 拾音 Shiyin：需求規格

> 狀態：已確認（2026-10-15，第二版：改成 macOS 原生 app）
> 本文件定義「要做什麼」。怎麼做寫在 `design.md`，實作順序寫在 `tasks.md`。

## 1. 背景

目前做會議紀錄的流程（一個 Claude Code 的 meeting-notes skill）：

1. 用另一個本機轉錄工具轉錄（Breeze ASR 25 + mlx-whisper）
2. 逐字稿上傳到公司內部的會議系統
3. 在 Claude 對話裡下指令，讓 Claude 整理、出待確認題目、校稿、定稿

這個流程有兩個問題：每一步都要在 Claude 對話裡下指令；資料存在外部的會議系統，要依賴外部系統。

## 2. 目標

做一個 macOS 原生 app，能在 app 裡錄音或匯入錄音，在本機轉錄，然後在同一個視窗裡看逐字稿、摘要和詳細內容。全程不依賴任何外部系統。

## 3. 使用者與環境

- 使用者：只有一個人（作者本人），在自己的 Mac 上使用，不對外散布
- 硬體：Apple Silicon Mac（M3 Pro、18 GB RAM），macOS 26
- 前置條件：
  - Homebrew 的 `ffmpeg`
  - 整理時要用的 `claude` CLI 或 `codex` CLI 已經登入
  - 要從原始碼建置的話，需要 Xcode 26

## 4. 資料與對外連線原則

| 項目 | 原則 |
|---|---|
| 錄音檔 | 一律不離開本機，也不放進 iCloud 會同步的資料夾 |
| 轉錄 | 完全離線，模型存在本機 |
| 整理（摘要、待確認、校稿） | 透過本機的 `claude` 或 `codex` CLI，**會把逐字稿文字送到 Anthropic 或 OpenAI**。設定成「不整理」就完全離線 |
| 資料存放 | `~/Library/Application Support/Shiyin`，資料夾權限 700。專案資料夾在有開 iCloud 同步的桌面，所以裡面不放資料 |

## 5. 範圍外（第一版不做）

- 多人共用或同步、散布給別人用（簽章、公證、自動更新）
- Intel Mac、macOS 26 以前的版本
- 跟外部會議系統同步或匯出；匯入外部會議系統上的舊會議
- 分辨說話者（Breeze ASR 25 不支援）
- 跨會議全文搜尋
- 手動編輯會議紀錄的文字（修改會議紀錄只能透過校稿和全文取代）
- 邊錄音邊即時轉錄

## 6. 功能需求

驗收條件的格式是「當…，系統應…」。

### R1 匯入錄音

- R1.1 系統應接受 ffmpeg 讀得到的音訊和影片檔（至少包含 m4a、mp3、wav、aac、flac、mp4、mov）。匯入方式有四種：
  - 拖進視窗
  - 工具列按鈕或 ⌘O
  - 拖到 Dock 圖示上
  - 在 Finder 用「打開方式」選拾音
- R1.2 從視窗匯入（拖曳、按鈕、⌘O）時，應跳出對話框，可以填標題、會議日期、與會者，三個都可以不填。一次匯入多個檔案時，每個檔案各成一場會議。
- R1.3 從 Dock 或 Finder 匯入時不跳對話框，直接用預設值建立會議並開始轉錄，再把視窗切到那一場會議。
- R1.4 會議日期預設值：檔名裡有日期（例如 `0827`、`8_27`、`2026-08-27`）就用檔名的日期，年份取不晚於今天的最近一年；檔名沒有日期才用檔案的修改日期。
- R1.5 系統應把錄音檔複製到資料資料夾，原始檔被刪掉也不影響（例如語音備忘錄的暫存檔過幾分鐘就會被系統清掉）。
- R1.6 匯入後，會議應立即出現在列表裡，狀態顯示「排隊中」。

### R2 本機轉錄

- R2.1 系統應用 Breeze ASR 25（mlx-whisper）在本機轉錄，不連網。
- R2.2 一次只轉錄一場，其他的照順序排隊。
- R2.3 轉錄中應顯示進度百分比和預估剩餘時間。
- R2.4 系統應把詞彙表放進轉錄提示詞，提示詞總長度上限 150 字。
- R2.5 系統應丟掉 Whisper 在靜音段常見的幻覺字串（沿用 `transcribe.py` 的規則），並標出低信心段落。
- R2.6 當轉錄失敗時，系統應顯示錯誤原因，並可以重試。
- R2.7 排隊中或轉錄中的工作應可以取消。
- R2.8 當 app 在工作進行中被關掉，下次開啟時系統應從頭重跑那項工作。

### R3 整理成會議紀錄

- R3.1 轉錄完成後，系統應自動整理（可在設定裡關掉）。
- R3.2 會議紀錄應包含以下內容：
  - 標題：使用者沒填才產生，20 字以內
  - 摘要重點
  - 詳細：依議題分段，每段有開始時間點和重點
  - 決議
  - 待辦：負責人、事項、期限
  - 未決問題
  - 待確認項目：最多 8 題，每題附時間點
- R3.3 整理規則（沿用 meeting-notes skill）：
  - 用繁體中文、台灣用語
  - 負責人只填明確提到的人
  - 期限依會議日期換算成 `yyyy-MM-dd`，星期幾要算對；不明確就留空並列成待確認
  - 推測出來的專有名詞和人名一定要列成待確認
  - 待確認項目要合併相近的問題，只問會影響紀錄正確性的地方
- R3.4 整理工具可在設定裡選 Claude 或 Codex。
- R3.5 應可以手動重新整理。
- R3.6 當整理失敗時，系統應顯示錯誤原因，並可以重試，逐字稿不受影響。

### R4 逐字稿

- R4.1 逐字稿應逐段顯示開始時間點，低信心段落要標示出來。
- R4.2 點時間點應從那裡開始播放錄音；播放時，目前那一段要高亮並自動捲到畫面內。
- R4.3 應可以搜尋逐字稿裡的關鍵字，並標出符合的段落。
- R4.4 應可以編輯單一段落的文字。
- R4.5 應可以全文取代（用詞修正），會議紀錄裡同一個詞也要一起改；可以選擇把正確的寫法加進詞彙表。

### R5 摘要與詳細

- R5.1 會議頁應分成四個分頁：摘要（摘要重點、決議、待辦、未決問題）、詳細、逐字稿、待確認。待確認分頁要顯示題數。
- R5.2 「詳細」和「待確認」裡的時間點應可以點，點了就跳到錄音的那個位置播放。
- R5.3 視窗底部應有一條錄音時間軸，畫出整場會議的段落、低信心段落和待確認題目的位置；點任何一處就跳到那裡播放。

### R6 待確認與校稿

- R6.1 每一題待確認項目都應可以輸入答案，也可以略過。
- R6.2 送出答案後，系統應讓 Claude 或 Codex 依答案修正會議紀錄。如果只有略過、沒有答案，就直接移除那些題目，不呼叫 LLM。
- R6.3 會議紀錄每次被修改（整理、校稿、全文取代）都應保留前一版，並可以復原上一版。

### R7 會議管理

- R7.1 會議列表應依會議日期由新到舊排列，並顯示每場的狀態：錄音中、排隊中、轉錄中 n%、整理中、待確認 n 題、完成、失敗。可以用標題篩選。
- R7.2 應可以修改標題、會議日期、與會者。
- R7.3 應可以刪除會議，錄音檔也一起刪掉；刪除前要確認。
- R7.4 應可以把會議紀錄匯出成 Markdown，可以存檔，也可以複製到剪貼簿。

### R8 詞彙表

- R8.1 應可以新增、刪除詞彙。
- R8.2 詞彙表應同時用在轉錄提示詞（R2.4）和整理（R3）。

### R9 設定與環境檢查

- R9.1 設定項目包括：整理工具（Claude、Codex、不整理）、模型（選填）、轉錄完成後是否自動整理。
- R9.2 應顯示環境檢查結果：ffmpeg、Python 環境、轉錄模型、`claude` CLI、`codex` CLI 是否可用；不能用的項目要附上修正方法。

### R10 安裝與首次設定

- R10.1 應有一個建置腳本，從原始碼產生 `Shiyin.app`，並可以選擇直接安裝到 `~/Applications`。
- R10.2 第一次開啟、環境還不齊全時，app 應顯示首次設定畫面，按一個按鈕就執行安裝腳本：
  - 建立 Python 環境、安裝 mlx-whisper
  - 準備轉錄模型：本機的另一個轉錄工具已經有 Breeze ASR 25 模型的話，就用 APFS clone 複製，不佔額外空間；沒有就從 Hugging Face 下載（這是唯一一次對外連線）
  - 安裝過程要即時顯示輸出
- R10.3 安裝腳本應可以重複執行，已經完成的步驟要跳過。

### R11 App 內錄音

- R11.1 應可以從工具列、選單列圖示或 ⌘R 開始和停止錄音。
- R11.2 錄音中應顯示經過時間和即時音量表。
- R11.3 停止錄音後，系統應自動建立會議（日期是今天）並開始轉錄。
- R11.4 關掉主視窗時錄音應繼續。從選單列圖示可以看到錄音狀態，也可以停止。
- R11.5 錄音格式要能承受 app 意外結束：已經錄到的內容不能整段遺失。
- R11.6 沒有麥克風權限時，系統應說明怎麼到「系統設定」開啟。
- R11.7 錄音中結束 app 應先確認；確認後，系統應先存好錄音再結束。

### R12 系統通知

- R12.1 轉錄完成、整理完成、工作失敗時，系統應發 macOS 通知。整理完成的通知要附上待確認題數。
- R12.2 點通知應打開那一場會議。
- R12.3 使用者沒有允許通知時，不影響其他功能。

### R13 選單列圖示

- R13.1 拾音執行時，選單列應常駐一個圖示，圖示要能區分三種狀態：閒置、錄音中、工作進行中。
- R13.2 選單內容包括：開始或停止錄音（錄音中顯示經過時間）、目前工作與進度、排隊數量、打開拾音、結束。
- R13.3 關掉主視窗時 app 不結束，工作和錄音都照常進行；從 Dock 或選單列可以重新打開視窗。
- R13.4 有工作在跑時結束 app 應先確認，並說明下次開啟會從頭重跑。

### R14 使用說明（2026-10-15 新增）

- R14.1 環境就緒後第一次進入主畫面時，應自動打開使用說明一次。
- R14.2 應可以隨時從「輔助說明」選單（⌘?，系統的 Help 選單在繁中 macOS 叫「輔助說明」）、沒有會議時的空白畫面、選單列再打開使用說明。
- R14.3 內容應依使用順序說明：錄音或匯入 → 轉錄 → 看會議紀錄 → 回答待確認 → 對照錄音 → 修正錯字與匯出；另外說明怎麼切換整理工具（Claude、Codex、不整理）、詞彙表、資料存放與隱私、快捷鍵。
- R14.5 應列出系統需求：晶片、macOS 版本、記憶體、磁碟空間、需要先安裝的工具，以及哪些步驟需要網路。數字要以實測為準（2026-10-15 在 M3 Pro、18 GB 上實測：轉錄時記憶體峰值約 7.5 GB；Python 環境 1.3 GB、模型 2.9 GB）。
- R14.4 說明裡提到的按鈕、分頁、選單名稱，應與介面上的文字完全一致。

## 7. 非功能需求

- N1 安全
  - app 不開任何網路連接埠
  - 呼叫外部程式時一律用參數陣列，不經過 shell 字串，避免指令注入
  - 存錄音檔一律用 `<會議 id>.<副檔名>` 命名，不使用原始檔名
- N2 隱私：逐字稿和會議紀錄不寫進 log。送給 LLM 時用暫存資料夾，用完就刪。
- N3 效能
  - 轉錄速度約 4～7 倍速（一小時的會議約 10～15 分鐘）
  - 轉錄和整理都不能讓介面卡住
- N4 介面
  - 使用 macOS 原生元件，遵循系統的淺色、深色模式
  - 常用操作要有鍵盤快捷鍵
  - 繁體中文介面
- N5 錄音中和轉錄中應避免系統進入閒置睡眠。
