# 拾音官網：需求（2026-10-17，已確認）

## 為什麼

使用者要讓拾音更產品化：有一個正式的官網介紹產品、提供下載、列出每次更新的內容，並且推上 GitHub 後自動部署到 Cloudflare。現在對外只有 GitHub 的 README 和 Releases 頁，對不寫程式的人來說不夠清楚，也不像一個產品。

## 給誰看

- **主要**：在 Mac 上工作、開會講台灣中文夾英文（或日文）、在意會議內容不外流的人。例如 PM、工程師、顧問、公司不允許雲端錄音機器人的人。
- **次要**：在 Threads、社群看到分享點進來的人，先要在 10 秒內看懂「這是什麼、跟別的有什麼不一樣、能不能用」。

## 網站要做到的事（依重要性）

- W1 一眼看懂：首頁第一屏就要說清楚「Mac 上的會議紀錄 app，錄音不出電腦，每一條紀錄都點得回原話」，並且可以直接下載。
- W2 說清楚跟其他工具哪裡不同：錄音留在本機、台灣中文夾英文、AI 會標出它沒把握的地方、用你已經有的 Claude 或 ChatGPT 訂閱。
- W3 下載：按鈕永遠指向最新版的 DMG；旁邊寫清楚系統需求（macOS 26、Apple Silicon）和第一次打開要怎麼做（沒有 Apple 開發者簽章，要到隱私權與安全性按「仍要打開」）。
- W4 版本說明：每一版的更新內容，最新的在最上面。**發布新版後自動出現在網站上，不用另外改網站。**
- W5 隱私說明：哪些東西留在這台 Mac、哪些文字會送到你選的整理工具，講清楚。
- W6 繁體中文、英文、日文三種語言，預設繁體中文；頁首用下拉選單切換。app 介面只有中英文（日本的 macOS 會顯示英文），會議可以是中英日文，所以日文版要寫清楚介面是英文。
- W7 自動部署：推到 main（改了網站）或發布新版時，自動部署到 Cloudflare Pages，不用手動上傳。
- W8 分享出去好看：在 Threads、Facebook、LINE 貼連結時有標題、說明和預覽圖。
- W9 基本品質：手機也能看、深色模式、鍵盤可以操作、開啟速度快、不用 cookie、不追蹤訪客。

## 頁面

| 頁面 | 網址 | 內容 |
|---|---|---|
| 首頁 | `/`、`/en/`、`/ja/` | 一句話介紹、真實截圖、怎麼用、隱私與整理工具、系統需求與下載、最近更新、常見問題 |
| 版本說明 | `/changelog/`、`/en/changelog/`、`/ja/changelog/` | 每一版的更新內容，附發布日期和下載連結（日文版顯示英文的更新內容） |
| 下載 | `/download` | 直接轉到最新版的 DMG，給 README、社群貼文用的固定連結 |
| 找不到頁面 | 404 | 說明找不到，給回首頁和版本說明的連結 |

## 不做（這一版）

- 部落格、使用者帳號、留言、電子報訂閱
- 線上說明文件（使用說明在 app 裡已經有）
- 付費、授權
- 網站分析（可以之後加 Cloudflare Web Analytics，它不用 cookie）

## 已決定

1. 首頁標題：「Mac 上的會議紀錄 app」（design §5）。
2. 網址：先用 Cloudflare 給的 `shiyin.pages.dev`；名稱被用走或之後接自己的網域時，設定 `SHIYIN_SITE_URL` 就好（design §8）。
3. 語言：中文、英文、日文，頁首下拉選單切換（2026-10-17 使用者要求）。日文版的版本說明用英文那一段，不要求每次發布多寫日文。
4. 視覺：第一版的青瓷綠色塊、宋體大標、假的 app 視窗太像 AI 產生的頁面，改成白底、系統字體、真截圖（design §3）。

## 需要使用者做的事

Cloudflare 的帳號設定只有你能做：建立 API token（權限 Cloudflare Pages：Edit）、找到 Account ID，加到 GitHub repo 的 Secrets。design §8 有步驟。

## 驗收

- 首頁、版本說明在桌機和手機寬度、淺色和深色都截圖檢查過，沒有跑版
- 下載按鈕和 `/download` 都下載到最新版 DMG
- 用測試 tag 確認：發布新版後，版本說明自動出現新的一版、下載連結換成新版
- 推一個只改網站的 commit 到 main，Cloudflare 自動部署
- Lighthouse 效能、無障礙都 95 分以上
- 分享預覽：用 Facebook 和 Threads 的連結預覽工具看過標題、說明和圖
