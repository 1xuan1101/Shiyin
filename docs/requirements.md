# 拾音 Shiyin 3.0：需求規格

> 狀態：已確認（2026-10-15，第三版；使用者以「全部做好再找我」授權開工）
> 第二版（只有自己用、依賴 Python）的規格保留在 `docs/archive/v2/`。
> 本文件定義「要做什麼」。怎麼做寫在 `design.md`，實作順序寫在 `tasks.md`。

## 1. 為什麼有第三版

第二版能用，但只能在開發者自己的電腦上跑：要先裝 Homebrew、Python、ffmpeg，也缺少會議紀錄 app 該有的核心功能。第三版回到最根本的目標重新規劃：

> **做一個完整、可以發布給別人用的 macOS 原生會議紀錄 app。**

技術不沿用第二版的選擇，改依實驗數據決定（`docs/spikes/asr-engines.md`）。

## 2. 使用者與發布方式（2026-10-15 已確認）

- 使用者：公司同事和身邊的人，不一定是工程師，也不一定裝了開發工具。
- 發布方式：自己發布 DMG，不上 Mac App Store。原因是 app 要執行 claude、codex CLI，App Store 的沙盒不允許。
- 沒有 Apple Developer 帳號，所以不做公證。使用者第一次打開時要手動放行一次，安裝說明要教怎麼操作。
- 有些人沒有裝 claude 或 codex，要提供 Anthropic、OpenAI API key 的選項。

## 3. 範圍

### 3.0 必須做

- 錄音：麥克風，加上線上會議的系統聲音
- 即時逐字稿、錄音中做筆記
- 正式轉錄（Breeze ASR 25）、說話者辨識
- AI 會議紀錄：範本、待確認、手動編輯、每一條都能跳到錄音
- 匯入與匯出：錄音、逐字稿、會議紀錄、整場會議的封包
- 全文搜尋、倍速播放
- 首次使用引導、DMG 發布、從第二版遷移
- 資料夾、全域快捷鍵、app 內更新（原本列為 P1。使用者要求「全部做好」，2026-10-15 納入 3.0）

### 之後再做（3.1 以後）

行事曆整合（自動帶入會議名稱和與會者）、對會議提問、iPhone 版、多人即時協作、雲端同步。英文版排在 3.1（見第 9 節）。

### 不做

上 Mac App Store、支援 Intel Mac 或 macOS 26 以前的版本、把錄音上傳到任何雲端。

## 4. 資料與隱私原則

| 項目 | 原則 |
|---|---|
| 錄音檔 | 只存在本機，不會上傳。要匯出或分享都由使用者自己操作 |
| 轉錄（即時、正式） | 在本機完成，不連網 |
| 整理成會議紀錄 | 把逐字稿文字、使用者的筆記、詞彙表、會議基本資料，送到使用者選的服務（Claude、Codex、Anthropic API、OpenAI API）。選「不整理」就完全離線 |
| API key | 存在 macOS 鑰匙圈，不寫進檔案或 log |
| 使用數據 | 不收集，也不回傳任何統計 |
| 資料位置 | `~/Library/Application Support/Shiyin`，權限 700 |

## 5. 功能需求

驗收條件的格式是「當…，系統應…」。優先級：**P0** 是 3.0 一定要有；**P1** 是 3.0 盡量做到，來不及可以延到 3.1。

### R1 錄音（P0）

- R1.1 系統應可以錄麥克風，並讓使用者選擇輸入裝置。
- R1.2 系統應可以錄電腦播放的聲音，例如 Zoom、Google Meet、Teams、瀏覽器裡的線上會議。來源可以選「麥克風」「系統聲音」「兩者都錄」。
- R1.3 錄音中應可以暫停和繼續。
- R1.4 錄音中應顯示經過時間，以及每個來源各自的音量。
- R1.5 當 app 當掉或電腦突然關機時，最多只能遺失最後幾秒的錄音，下次開啟時要自動復原。
- R1.6 應可以連續錄音至少 4 小時。
- R1.7 關掉主視窗後錄音應繼續進行；從選單列可以看到錄音狀態，也可以暫停、停止。
- R1.8 第一次錄音時，應依序說明用途並請求麥克風和系統聲音權限。使用者拒絕的話，要說明到哪裡打開。
- R1.9 錄音中和轉錄中，系統不應進入閒置睡眠。

### R2 即時逐字稿與錄音中筆記（P0）

- R2.1 錄音中應即時顯示逐字稿：一講話就出現暫定文字，定稿延遲在 5 秒以內。
- R2.2 錄音中可以往回捲動看前面的內容；使用者正在往回看時，新文字進來也不要把畫面拉走。
- R2.3 錄音中可以自己打筆記，每一行都會記下當下的錄音時間。整理時 AI 會參考這些筆記。
- R2.4 錄音中可以按一個鍵標記「重點」。標記會顯示在時間軸上，整理時也會被當作重點。
- R2.5 即時逐字稿只是預覽。錄音結束後，改用正式轉錄的結果（R4）。

### R3 匯入（P0）

- R3.1 應可以匯入 macOS 讀得到的音訊和影片檔，至少包含 m4a、mp3、wav、aac、flac、caf、aiff、mp4、mov。匯入方式有四種：拖進視窗、⌘O、拖到 Dock 圖示、Finder 的「打開方式」。
- R3.2 會議日期預設從檔名推算（沿用第二版的規則），推算不出來就用檔案的修改日期。
- R3.3 應可以匯入整場會議的封包（.shiyin，見 R7.4），完整還原錄音、逐字稿、會議紀錄和筆記。
- R3.4 應可以匯入逐字稿檔（srt、vtt、txt），可以單獨匯入，也可以跟錄音一起。只有逐字稿時不用轉錄，直接整理。
- R3.5 應可以匯入 Markdown 檔，當成這場會議的使用者筆記。

### R4 正式轉錄（P0）

- R4.1 錄音結束或匯入後，系統應在本機用 Breeze ASR 25 轉錄，並把詞彙表帶進去當提示。設定裡可以改用 macOS 內建的語音辨識：不用下載模型、速度快很多，但不吃詞彙表（2026-10-15 依真人會議的實測加入，見 D11）。
- R4.2 轉錄中應顯示進度和預估剩餘時間，並且可以取消、重試；app 中途被關掉的話，下次開啟時自動重跑。
- R4.3 一次只轉錄一場，其他場排隊等待。
- R4.4 辨識信心低的段落要標示出來。
- R4.5 使用者不需要安裝 Python、Homebrew 或 ffmpeg。

### R5 說話者辨識（P0，要先通過實驗）

- R5.1 正式轉錄時，系統應分出不同的說話者，逐字稿每一段都標上「說話者 1」「說話者 2」等標籤。
- R5.2 使用者可以幫說話者改名。改名後，整場的逐字稿和會議紀錄都改用新名字。
- R5.3 整理時，AI 要知道每段話是誰說的；待辦的負責人優先使用說話者的名字。
- R5.4 如果實驗結果準確度太差（判斷標準寫在 tasks.md），可以把這項延到 3.1，但要先跟使用者確認。

### R6 會議紀錄（P0）

- R6.1 整理工具可以選 Claude（claude CLI）、Codex（codex CLI）、Anthropic API、OpenAI API，或「不整理」。選 API 的話，要填 API key，也可以選模型。
- R6.2 應提供範本：一般會議、一對一、訪談、課堂／演講、腦力激盪。使用者也可以自己新增範本，自訂要哪些段落、每個段落怎麼寫。每場會議可以選範本，換了範本之後可以重新整理。
- R6.3 會議紀錄依範本包含以下內容：標題、摘要、決議、待辦（負責人、期限）、未決問題、依議題分段的詳細內容、自訂段落、待確認。
- R6.4 **每一條紀錄都要附上錄音時間點**，點一下就從錄音的那個位置開始播放（「秒聽紀錄」）。
- R6.5 待確認與校稿沿用第二版：回答題目後，AI 依答案修正紀錄；略過的題目直接移除。
- R6.6 使用者可以直接編輯會議紀錄，包括新增、刪除、修改條目。
- R6.7 每次修改都要留版本，並可以復原。修改包括 AI 整理、校稿、手動編輯、用詞修正。
- R6.8 整理規則沿用第二版：期限要換算成實際日期、負責人只填明確提到的人、推測出來的專有名詞要列進待確認。

### R7 匯出與分享（P0）

- R7.1 錄音可以匯出成 m4a（AAC）或 wav。
- R7.2 逐字稿可以匯出成 txt、srt、vtt、Markdown；docx 是 P1。匯出時可以選擇要不要包含時間點和說話者。
- R7.3 會議紀錄可以匯出成 Markdown、PDF；docx 是 P1。也可以複製成純文字、Markdown 或富文字，直接貼到 Notion、Slack、Word。
- R7.4 整場會議可以打包成 .shiyin 檔，內容包含錄音、逐字稿、說話者名字、會議紀錄、筆記和重點標記，用來備份或傳給同事。
- R7.5 匯出的檔案可以用 macOS 的分享選單（Mail、AirDrop、訊息）分享出去。

### R8 播放與逐字稿（P0）

- R8.1 沿用第二版的功能：同步播放、播放中的段落高亮、底部時間軸、點時間點跳播、搜尋、單段編輯、用詞修正（會一起改到會議紀錄，也可以加進詞彙表）。
- R8.2 可以倍速播放：0.75×、1×、1.25×、1.5×、2×。
- R8.3 逐字稿要顯示說話者，也可以篩選成只看某一位說話者的內容。
- R8.4 時間軸上要標出重點標記和待確認題目的位置。

### R9 管理（P0）

- R9.1 全文搜尋：輸入一個關鍵字，同時搜尋所有會議的標題、逐字稿、會議紀錄和筆記，點搜尋結果可以直接跳到那個位置。
- R9.2 資料夾：每場會議可以放進一個資料夾（例如專案名稱、客戶名稱）。側欄可以切換只看某個資料夾；資料夾可以改名、刪除（刪除資料夾不會刪掉會議）。在某個資料夾裡錄音或匯入，新會議就放進那個資料夾。.shiyin 封包會帶著資料夾名稱。
- R9.3 刪除的會議先放進垃圾桶，30 天後才永久刪除；在這之前都可以還原。
- R9.4 儲存空間：轉錄完成後，錄音自動轉成 m4a 以節省空間（可以在設定裡關掉）；設定裡要看得到總共用了多少空間。

### R10 安裝、首次使用、更新（P0）

- R10.1 以 DMG 發布：打開後把 app 拖進「應用程式」資料夾。附上一頁安裝說明，教使用者怎麼放行第一次開啟。
- R10.2 第一次開啟時要有引導，依序完成：介紹 app、請求權限、下載轉錄模型、設定整理工具。
- R10.3 下載模型時要顯示進度，可以暫停和繼續；斷線後可以接著下載；下載完成後要驗證檔案正確。
- R10.4 使用說明沿用第二版的 R14，內容依第三版的功能更新。
- R10.5 從第二版升級時，原本的會議、逐字稿、會議紀錄、詞彙表都要保留。第二版的 Python 環境和舊模型已經用不到，要提示使用者可以刪除，大約可以釋放 4.2 GB。
- R10.6 更新：app 會定期檢查新版本（設定裡也可以手動檢查），有新版時詢問使用者，同意後自動下載、驗證、替換並重新開啟。下載的檔案要驗證完整性，而且新版 app 的簽章要跟目前的 app 相符，否則拒絕安裝。錄音或轉錄進行中不能更新。更新後資料不能遺失，資料庫要自動遷移。更新檔放在哪裡由發布的人決定（Q1），app 裡可以設定更新網址。
- R10.7 app 更新後，麥克風和系統聲音權限不需要重新允許。

### R11 系統整合（P0）

- R11.1 選單列：錄音控制（開始、暫停、停止、經過時間）、目前工作的進度、打開主視窗、使用說明、結束。
- R11.2 通知：轉錄完成、會議紀錄整理好（附待確認題數）、失敗時都要通知；點通知會打開那場會議。
- R11.3 全域快捷鍵：在其他 app 裡按 ⌃⌥⌘R 也能開始或停止錄音；可以在設定裡關掉。

## 6. 非功能需求

- N1 隱私：見第 4 節。
- N2 效能：以 M1 作為下限估算，以 M3 Pro 的實測為準。
  - 即時逐字稿：暫定文字在 1 秒內出現
  - 正式轉錄：至少 5 倍速
  - 整理一小時的會議：扣掉 CLI 或 API 的回應時間，app 本身的處理不超過 10 秒
  - 任何工作在進行時，介面都不能卡住
- N3 穩定：錄音不能遺失（R1.5）；任何失敗的工作都要能重試；資料庫遷移失敗時不能損毀原本的資料，所以遷移前要先備份。
- N4 系統需求：
  - Apple Silicon（M1 以上）、macOS 26 以上
  - 記憶體：8 GB 以上。app 內轉錄加說話者辨識的峰值約 2.7 GB，4 小時的會議約 4.1 GB（實測）
  - 磁碟：模型約 1.7 GB（轉錄 1.66 GB＋說話者辨識 21 MB），加上錄音（m4a 實測約每小時 10～30 MB）
- N5 介面：繁體中文；使用 macOS 原生元件；支援深色、淺色模式；常用操作都有鍵盤快捷鍵；VoiceOver 能讀出主要元件。
- N6 安全：不開任何網路連接埠；呼叫外部程式一律用參數陣列；API key 存在鑰匙圈。
- N7 可維護性：沿用 SDD 流程；DEBUG 版保留 shiyinctl 控制通道，用來做驗證。

## 7. 待確認問題（使用者還沒回答，先照預設進行）

預設處理方式：
- Q1：還沒有發布位置。R10.6 的更新機制先做好，更新網址留空，決定位置後在建置時帶入或在設定裡填
- Q2：還沒有真實錄音。轉錄先用 `say` 合成的錄音驗證；說話者辨識用合成聲音測不出來（見 `docs/spikes/asr-engines.md`），改用公開的 AMI 真人會議錄音。中文真實錄音的驗證（T-A1）留給使用者
- Q3：只做繁體中文介面


- Q1 **DMG 要放在哪裡給同事下載？** 例如公司的 Google Drive、NAS、內部網站或 GitHub。R10.6 的自動更新也需要一個固定的網址。
- Q2 **真實的會議錄音**：需要一段真實會議的錄音，最好是多人、中英夾雜，用來驗證轉錄引擎和說話者辨識（T-A1、T-A3）。
- Q3 介面只做繁體中文就好嗎？目前規劃把英文介面延到 3.1。

## 9. 第 3.1 版：英文版（2026-10-16，使用者已確認）

### 為什麼

專案要開源。英文介面讓看不懂中文的人也能使用、參與開發；台灣使用者也常有全英文的會議。產品定位維持繁體中文優先：在英文市場，拾音跟 Char（原 Hyprnote）、Granola 比沒有明顯優勢，真正的特色是台灣口音、中英夾雜的轉錄。

使用者的決定（2026-10-16）：介面和英文會議都要做；介面語言跟著 macOS 系統語言。

### R12 多語言（P0）

- R12.1 介面語言跟著 macOS 的語言設定：繁體中文（含台灣、香港）顯示中文，其他語言顯示英文。使用者也可以在「系統設定 → 一般 → 語言與地區」單獨指定拾音的語言。
- R12.2 所有介面文字都要有英文：選單、按鈕、提示、錯誤訊息、通知、狀態、使用說明、首次使用引導、設定、匯出對話框。日期、星期、會議長度依介面語言的格式顯示。
- R12.3 系統權限詢問的說明文字、app 的顯示名稱（英文是 Shiyin）也要有英文。
- R12.4 每場會議有「會議語言」：中文或英文。新的錄音和匯入預設用「設定 → 錄音」的預設會議語言（預設值依介面語言），開始錄音和匯入時都可以改；會議頁也可以改，改了之後可以重新轉錄、重新整理。
- R12.5 會議語言決定三件事：即時逐字稿的辨識語言、正式轉錄的語言和提示詞（Breeze 和 macOS 內建都是）、會議紀錄的輸出語言。中文會議的行為跟 3.0 完全一樣。
- R12.6 內建範本的名稱和說明依介面語言顯示；英文會議的紀錄用英文段落（自訂段落的標題也翻成英文）。使用者自訂的範本照原樣。
- R12.7 匯出的會議紀錄和逐字稿，標題與欄位名稱（摘要、決議、說話者…）用那場會議的語言。
- R12.8 README、DMG 裡的安裝說明都有英文版。

### 不做

- 其他介面語言（日文、簡體中文等）
- 一場會議裡中英文各半的特別處理（中文會議本來就能處理中英夾雜）
- 把會議紀錄翻譯成另一種語言

### 驗收

- 英文系統：從首次使用引導開始，錄一場英文會議（AMI 片段模擬）走完全流程，畫面上沒有中文；即時逐字稿、正式逐字稿、會議紀錄、匯出都是英文
- 繁中系統：既有會議和一場新的中文會議，行為和 3.0 一致
- 檢查腳本確認翻譯表沒有缺少的英文，程式碼裡沒有漏掉沒查表的中文介面文字
